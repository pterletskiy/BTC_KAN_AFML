Daily Volatility · EWMA

Exponentially-weighted moving standard deviation of log returns, with span 50:

EWMA volatility σt = √( EWMAspan=50[ rt2 ] )

Why span 50, not 100. López de Prado's default for equities is 100; BTC's regime-cycle is shorter, so 50 reacts faster to volatility shifts.

Two downstream uses:

  • Sets the CUSUM threshold (Step 3).
  • Sets the profit-take and stop-loss barrier widths in triple-barrier labeling (Step 4).

One volatility estimate, two roles. This is what couples sampling and labeling to the prevailing market regime.

Phase I · Step 03 7 / 24

CUSUM Filter · event sampling

Don't label every bar. Label only the bars where something economically meaningful has accumulated.

Recursion
Positive cumulative deviation st+ = max(0, st-1+ + rt − E[r])
Negative cumulative deviation st− = min(0, st-1− + rt − E[r])
Trigger condition | st± | ≥ h · σt

h = 1.5 (multiplier on daily volatility). When triggered, fire an event and reset the corresponding accumulator to 0.

The intuition. Returns drift around a small mean. s+ counts how much price has accumulated above the mean since the last reset. When that accumulation exceeds 1.5 daily-volatility units, the regime has shifted enough to warrant labeling.

Output: ≈ 1,245 events from ≈ 4,200 bars (~30%). The rest is noise.

Phase I · Step 04 8 / 24

Triple-Barrier Labeling

For each event from CUSUM, place three barriers around the entry price. Whichever barrier is touched first determines the label.

The three barriers
  • Profit-taking (PT) — horizontal line above entry at +1.5 · σt. If hit first → label +1.
  • Stop-loss (SL) — horizontal line below entry at −1.5 · σt. If hit first → label −1.
  • Vertical timeout — entry time plus 10 calendar days. If reached without hitting PT or SL → label = sign(final return).

Why this beats fixed-time-horizon labels. Fixed labels use the same horizon for every event regardless of regime. Triple-barrier adapts horizon to volatility (the σt scales) and lets the path itself decide the outcome.

Class balance after dropping the rare class: { +1: 697 (56.0%),  −1: 548 (44.0%) } → 1,245 events.

Phase I · Step 05 9 / 24

Sample Weights · why and how

Financial returns are not independent and identically distributed. A vanilla classifier that treats every label equally is double-counting information.

Why · two failures of equal weighting

1. Unequal information content. A day where BTC moves +7% carries more signal about the prevailing regime than a day where it moves +1%. Vanilla weighting gives both weight 1.

2. Overlapping observations. A label starting at t0 with a 10-day horizon shares 8 bars with a label starting at t0+2. If both are positive, the model effectively sees the same regime twice.

AFML Section 4.6 corrects both effects with a single weighting scheme: weight is proportional to the absolute log-return attributed uniquely to that label, divided by the number of concurrent labels.

Phase I · Step 05 9 / 23

Sample Weights · why and how

Financial returns are not independent and identically distributed. A vanilla classifier that treats every label equally is double-counting information.

Why · two failures of equal weighting

1. Unequal information content. A day where BTC moves +7% carries more signal about the prevailing regime than a day where it moves +1%. Vanilla weighting gives both weight 1.

2. Overlapping observations. A label starting at t0 with a 10-day horizon shares 8 bars with a label starting at t0+2. If both are positive, the model effectively sees the same regime twice.

AFML Section 4.6 corrects both effects with a single weighting scheme: weight is proportional to the absolute log-return attributed uniquely to that label, divided by the number of concurrent labels.

How · five-step calculation
  1. Concurrent labels ct. For each daily bar, count how many labels are alive (their span includes that bar).
  2. Average uniqueness. For each label, average 1 / ct over its span. No-overlap label → uniqueness ≈ 1; heavy-overlap label → uniqueness ≈ 0.
  3. Return attribution. Multiply uniqueness by |rt| at barrier touch. Decisive moves carry more weight.
  4. Time decay. Linear decay from 0.4 (oldest label) to 1.0 (newest). Older labels weigh less.
  5. 99th-percentile cap. No single event dominates training.
Final weight (per label) wi ∝ ūi · |ri| · di,   mean(w) = 1

CPCV Split Generation

Combinatorial Purged Cross-Validation. Reuses every observation across multiple test folds, producing five reconstructed backtest paths instead of one.

Configuration
  • N = 6 contiguous time-ordered groups, k = 2 test groups per split.
  • Splits = C(6, 2) = 15; reconstructed paths = 5.
  • Embargo = 1% of bars after each test group; observations whose t1 spans a test group are purged from training.
Why CPCV beats walk-forward and K-fold

Walk-forward measures robustness on a single timeline. K-fold leaks the future into training when labels overlap. CPCV combines the two: each event appears in multiple test folds across paths, giving 5 path-level Sharpe estimates — enough variance for a meaningful Probability of Backtest Overfitting.

Phase II · Step 08 12 / 23

CPCV Split Generation

Combinatorial Purged Cross-Validation. Reuses every observation across multiple test folds, generating five reconstructed backtest paths instead of one.

Configuration
  • N = 6 contiguous time-ordered groups. Each group is a chronological slice of events.
  • k = 2 test groups per split. The remaining N − k = 4 form the train set.
  • Splits = C(6, 2) = 15. Every pairwise combination of test groups is enumerated.
  • Reconstructed paths = 5. Each event ends up in exactly one test fold per path; assembling all paths gives full coverage.
  • Embargo = 1% of bars. Observations within the embargo window after each test group are dropped from the training set.
Why CPCV beats the alternatives

Walk-forward CV uses each event in only one test fold — the temporal one — so robustness to regime changes is measured against a single timeline.

K-fold CV ignores chronology and freely leaks the future into training when labels overlap.

CPCV combines both. Each event appears in multiple distinct test folds (across paths), giving 5 path-level Sharpe estimates per model — enough variance to compute a meaningful Probability of Backtest Overfitting.

Purging. For each split, observations whose t1 overlaps the test fold are dropped from training. This is what closes the leakage door that K-fold leaves open.

Phase II · Step 09 13 / 23

Per-Fold Preprocessing · FFD & Robust Scaling

Both transformations are fitted on the train fold only and applied to test. No global transformation, no leakage.

Fractional Differencing · AFML Ch. 5

Problem. Most price-derived features carry a unit root (non-stationary). Standard first-differencing makes them stationary but destroys long memory: the resulting series has zero autocorrelation at every lag.

Solution. Differentiate fractionally with order d ∈ (0, 1). Choose the smallest d that passes the ADF stationarity test. Memory is preserved up to that minimum required differencing.

Fractionally differenced series x̃t(d) = Σk=0∞ ωk(d) · xt-k

Applied to ATR (cumulative-volume-like behavior, large dynamic range). Other features are bounded or already stationary.

Robust Scaling

Why not StandardScaler. Crypto returns are fat-tailed: extreme observations skew mean and standard deviation. A model trained on standard-scaled features picks up on those extremes as scale, not signal.

RobustScaler. Center on the median, scale by the IQR (interquartile range). The median is unaffected by outliers; the IQR captures bulk-of-the-distribution spread.

Per-feature scaling x̃ = (x − median(x)) / IQR(x)

Per-fold fit. Computed on the train fold only, then applied to the test fold without recomputation. This is the same per-fold contract as FFD.

Phase II · Step 10 14 / 24

Per-Fold Preprocessing · Multi-Model MDA

Each model votes for its own top features. The union becomes the selected set. Computed inside every training fold.

How MDA works

Mean Decrease Accuracy measures feature importance by removing each feature's predictive power and watching what happens to model performance.

  1. Train a model on the full feature set; record its baseline F1 score on the validation fold.
  2. For each feature in turn, shuffle that column's values across the validation set — this destroys whatever signal the feature carried while keeping its marginal distribution intact.
  3. Re-evaluate the model on the shuffled set; record the new F1.
  4. The drop ΔF1 = F1baseline − F1shuffled is that feature's importance.

Big drop → the feature was carrying real signal. No drop → the model was ignoring it.

Standard López de Prado AFML procedure (Chapter 8); avoids the bias of impurity-based importances which are inflated for features with many splits.

Why two voters — LR & RF

A single-model MDA inherits that model's inductive bias. AFML defaults to Random Forest as the importance estimator, which is fine for non-linear interactions but blind to features that contribute mainly through linear combinations.

  • Logistic Regression votes on features useful in linear combinations. Linear interactions of macro / yield / volatility features tend to score highly here.
  • Random Forest votes on features useful in non-linear combinations. Trees discover thresholds and joint splits that linear models cannot.

Aggregation. Each voter ranks the 56 MDA-eligible features and keeps its top 40% (~22 features). The selected set is the union — a feature survives if either voter found it useful.

Why union, not intersection. Intersection would discard features informative for one architecture but not the other. The benchmarking goal is to give every model its best chance.

Lag features excluded. The 6 lag columns are filtered before MDA runs — pure autoregressive signal would otherwise compete with engineered features for the top-K cap and bias the comparison toward AR Logistic.

Phase II · Step 10 14 / 23

Per-Fold Preprocessing · Multi-Model MDA

Each model votes for its own top features. The union becomes the selected set. Computed inside every training fold.

Mean Decrease Accuracy

Definition. For each feature, permute its values across the validation set, re-evaluate the model, and measure how much accuracy drops. A feature that the model relies on causes a large drop; a useless feature causes none.

Why per-model. Different architectures rely on different features. A tree-based model finds RSI useful; a linear model may not. Computing MDA against a single proxy model would bias the ranking toward that model's family.

Five voters. Random Forest, XGBoost, Logistic Regression, LSTM, KAN. Each ranks the 56 MDA-eligible features.

Aggregation

Top-K fraction = 0.4. Each model's top 40% (≈ 22 features) form its candidate set. The selected feature set is the union of these candidate sets across the five models.

Why union, not intersection. Intersection would discard any feature that is informative for one architecture but not all. The benchmarking goal is to give each model its best chance, not to find a single common-denominator feature set.

Lag features excluded. The 6 lag columns are filtered out before MDA runs. Letting pure autoregressive signal compete for slot space against engineered features would bias the comparison toward the AR Logistic baseline.

Per-fold. MDA runs inside each of the 15 splits; the selected set can vary fold to fold.

Phase II · Step 11 15 / 24

Nested Hyperparameter Tuning

Each tuned model receives its own search budget inside every training fold. AFML Chapter 9 protocol: nested cross-validation plus a Bayesian search.

Nested 3-fold inner CV

Within each of the 15 outer CPCV folds, the train portion is split again into 3 purged inner folds. Every hyperparameter trial is scored as the mean F1 across those three inner folds, with the same purging logic protecting against label overlap.

Why nested. Tuning on the outer test fold would leak information back into model selection. The inner CV creates a clean validation set that the outer fold never sees.

Optuna TPE & MedianPruner

Tree-Structured Parzen Estimator. First 5 trials are random (Optuna's startup phase) — they explore the search space without prior knowledge. From trial 6 onward, TPE fits two density models (one over good past trials, one over bad) and samples new hyperparameters where the ratio favors good outcomes.

MedianPruner kills underperforming trials early. At each intermediate step (epoch for deep models, fold for classical), if the running F1 is below the median of all completed trials at the same step, the trial is stopped. Saves roughly 2×–3× on the deep-model search.

Termination. A fixed budget of 30 trials per fold per model. The search does not stop early on a "perfect" model; it always runs the full budget so every model gets the same exploration depth.

Phase II · Step 11 15 / 23

Nested Hyperparameter Tuning

Each tuned model receives its own search budget inside every training fold. AFML Chapter 9 protocol: nested cross-validation plus a Bayesian search.

Optuna · Tree-Structured Parzen Estimator

What TPE does. Models the conditional probability of hyperparameter values given good vs. bad past trial outcomes, then samples new candidates where the ratio favors good outcomes. Bayesian optimization without the GP overhead.

Budget per fold. 30 trials per model per fold. With 6 tuned models × 15 folds, that's 900 model fits per tuned configuration; the search budget is real.

Inner CV. 3-fold purged CV inside each train fold, with the same purging logic as the outer CPCV.

Median Pruner

Why pruning. Many trials are dead on arrival: extreme hyperparameters that diverge in the first few epochs. Letting them run to completion wastes the search budget on configurations the optimizer already knows are bad.

How it works. At each intermediate step (epoch for deep models, fold for classical), check whether the running performance is below the median of all trials at the same step. If so, stop the trial early.

Speedup. Roughly 2× to 3× depending on the model; the deep-learning models benefit most because their training is the most expensive.

Why per-fold tuning. Tuning capacity is part of what's being benchmarked. A single global hyperparameter set rewards whichever model happened to be tuned first; per-fold tuning gives every architecture a fair chance.

Step E

Probability → trading position. AFML Chapter 10. Position cap at 0.75; abstain below 0.05.
Why two calibrators

Platt scaling fits a single sigmoid σ(a · z + b) on raw scores. Two parameters, very robust on small validation sets. Ideal for binary outputs from classical models (LR, RF, XGBoost, AR Logistic).

Vector scaling fits per-class linear scaling on softmax logits before re-applying the softmax. More parameters but handles multi-class outputs natively. Used for LSTM and KAN, which output two-class softmax distributions.

Why it matters for the trade

The S-curve bet-sizing layer (AFML Ch. 10) converts P(Up) into position size. An overconfident model that says 0.8 when reality is 0.6 will be sized 0.5 standard deviations larger than it should be — and lose money on average.

Calibration is therefore not optional. It's the bridge between machine-learning output and trading position.

Phase III · Step 15 19 / 24

Symbolic Extraction · from KAN to closed-form formula

The novel contribution. Algorithm 1 from the VIX-KAN paper (Wu et al., 2024), adapted to the financial weak-signal regime.

Five-step procedure
  1. Train. Two-stage. First gradient descent with noisy inputs as regularization, encouraging robust splines (600 steps). Then a quasi-Newton optimizer with sparsity penalties (L1 + entropy) drives uninformative edges toward zero.
  2. Prune. Remove edges below the importance threshold. Architecture compresses, e.g., from [56, 12, 5, 2] to [5, 4, 2].
  3. Symbolic substitution. For each surviving edge, fit candidate primitives (polynomial, tanh, sin, cos, exp, log) and pick the one with highest R². Brute-force fallback if PyKAN's suggest_symbolic returns no match.
  4. Numerical fine-tuning. With primitive shapes locked, re-optimize the constants on the substituted model. Recovers some of the accuracy lost during substitution.
  5. Simplify. SymPy simplification pipeline (with 30s timeout) collapses redundant terms; final formula is human-readable.

Symbolic Extraction · from KAN to closed-form formula

The novel contribution. Algorithm 1 from the VIX-KAN paper (Wu et al., 2024), adapted to the financial weak-signal regime.

Five-step procedure
  1. Train. Two-stage. First gradient descent with noisy inputs as regularization, encouraging robust splines (600 steps). Then a quasi-Newton optimizer with sparsity penalties (L1 + entropy) drives uninformative edges toward zero.
  2. Prune. Remove edges below the importance threshold. Architecture compresses, e.g., from [56, 12, 5, 2] to [5, 4, 2].
  3. Symbolic substitution. For each surviving edge, fit candidate primitives (polynomial, tanh, sin, cos, exp, log) and pick the one with highest R². Brute-force fallback if PyKAN's suggest_symbolic returns no match.
  4. Numerical fine-tuning. With primitive shapes locked, re-optimize the constants on the substituted model. Recovers some of the accuracy lost during substitution.
  5. Simplify. SymPy simplification pipeline (with 30s timeout) collapses redundant terms; final formula is human-readable.
Architectural simplifications & output

Three deliberate simplifications. Single hidden layer (no width2 — two layers produce nested compositions that defeat SymPy). Coarse spline grid (3 instead of 5). Top 5 features only, ranked by selection frequency across all 15 KAN folds.

Fold selected: "last" — the most recent CPCV fold. Justification: signal closer to today's regime is more interpretable for a defense audience and a likely deployment.

Output form P(Up | x) = 1 / (1 + exp( −f(x1, …, x5) ))
where f is a sum of polynomial, tanh, and trigonometric terms in the 5 surviving features

What is reported. Pruned architecture, surviving features, the closed-form expression, pre-symbolic vs post-symbolic accuracy, and the symbolification rate (% of edges successfully replaced).

Part 05 · Discussion & Next Steps 22 / 23

Five honest limitations

Two from compute and data constraints; three from deliberate trade-offs in the protocol. Each frames a future-work direction.

L1

Computational power

Currently 2–3 seeds per model and 30 Optuna trials per fold; KAN width capped at 12. With more compute: more seeds, more trials, wider hyperparameter ranges.

L2

Daily OHLCV data only

Daily resolution discards intraday microstructure. Pipeline is timeframe-agnostic; an hourly extension would multiply the event count and unlock microstructure features.

L3

Symbolic extraction is fold-specific

Formula extracted from one CPCV fold (the last). Per-fold extraction would let us count which features and primitives recur — that's structural signal vs. one-off noise.

L4

Architectural simplifications

The symbolic-extraction model uses single hidden layer, grid = 3, top 5 features. Post-symbolic accuracy is therefore a lower bound on what a full-architecture KAN learns.

L5

No regime-conditional analysis

BTC has had ~5 distinct regimes over 2014–2026. Full-sample Sharpe averages over them. A regime-conditional analysis is left for future work, especially if DSR is near zero.

Before defense
